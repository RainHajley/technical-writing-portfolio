= SOP: Patient Data Sanitization
:id: SOP-HIT-094
:status: Internal
:compliance: HIPAA
:toc: right

Working with Protected Health Information (PHI) requires strict adherence to security protocols. Follow these standards to maintain compliance when handling patient metrics, histories, or logs.

== Storage Protocols

* *Centralize Data:* Store all patient-related data exclusively within hardware-encrypted company cloud directories.
* *Local Storage:* Do not download or cache raw PHI on local machines.
* *Access Control:* Set all new directories to *Restricted* upon creation. Grant access only to team members with explicit project requirements.

== Data Sanitization & Sharing

Scrub all data before including logs in documentation or sharing with project teams.

=== De-identification
Use authorized scripts to mask patient names, locations, dates, and account numbers.

=== Secure Sharing
Enforce the following for all shared sensitive documentation:
* *Password Protection:* Mandatory on all shared assets.
* *Link Expiration:* Set to a maximum of 7 days.
* *Communication:* Never share access tokens or links to raw data in public or cross-departmental channels.

[NOTE]
====
*Monthly Audits:* The security team performs randomized, automated audits on all repositories. Improper permissions or public links will trigger an immediate flag.
====

[WARNING]
====
*Compliance Risk:* Non-compliance results in an immediate security review and potential suspension of system access.
====
